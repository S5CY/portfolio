## 2. SDLC process used to update my portfolio

| SDLC stage | What I did | Evidence I can show |
|---|---|---|
| Plan | Read the checkpoint requirements and turned them into sections and a short demo path. | This page follows the four individual review prompts in order. |
| Analyze | Inspected the starter portfolio to find template text, existing projects, navigation, and configuration that needed personalization. | The home page and site settings now identify me instead of the template owner. |
| Design | Chose one checkpoint hub so the reviewer can reach every talking point quickly. | The home-page checkpoint card links directly here. |
| Implement | Updated the site configuration and home page, then added this checkpoint page. | The changed files are visible in Git history/diff. |
| Test | Checked the page metadata, links, repository changes, and local Jekyll build. | I can show the build result and click through the finished pages. |
| Deploy/reflect | Commit and push the tested changes, then record what worked and what to improve next. | The GitHub commit and published Pages site will be the final evidence. |

My short explanation: **I plan the smallest useful change, inspect the current code, design the page, implement it, test locally, then commit and deploy. I repeat that cycle for each improvement.**

## 4. My Unit 1–4 unicorn

My unicorn is an **interactive study-progress dashboard** that turns the Unit 1–4 learning trail into something useful instead of a static checklist.

The first version will:

- Display each unit as a progress card
- Link every unit to its strongest lesson or project artifact
- Let me mark practice items complete in the browser
- Show an overall completion percentage
- Include a reflection field for what I learned and what I need to revisit

This stands out because it combines the concepts from the first four units—data, variables, conditionals, iteration, and user interaction—inside a tool I can continue using throughout the course.
